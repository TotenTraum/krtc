# ADR-0013. SFU как встраиваемая KMP-библиотека

- Статус: Принято
- Дата: 2026-11-10
- Уточняет: [ADR-0010](0010-sfu-before-1.0.md), [ADR-0011](0011-sfu-kotlin-multiplatform.md)

## Контекст

krtc будет подключаться к другому серверу как библиотека. Сервер-хост написан на Kotlin Multiplatform (JVM и/или Kotlin/Native).

У хоста свои пользователи, авторизация, транспорт сигнализации, мониторинг и правила комнат. Раньше `krtc-sfu` был приложением: Ktor-сервер, `main` и тестовая страница лежали в одном модуле с ядром, все входящие допускались, внутренние классы были публичными.

## Решение

**Модули:**

```
krtc-signaling   протокол сигнализации: @Serializable ServerMessage / ClientMessage   (все таргеты)
krtc-sfu         ядро SFU, без HTTP. Публичное API — только типы встраивания            (jvm, macOS, Linux)
krtc-sfu-ktor    Route.krtcSfu(sfu, path): сигнализация по WebSocket для Ktor-хостов
krtc-sfu-server  готовое приложение: main, тестовая страница, /metrics (не библиотека)
krtc-client      клиент на тех же моделях krtc-signaling
```

**API встраивания** (`krtc.sfu`, остальное `internal`):

| Тип | Назначение |
|---|---|
| `Sfu(config)` | Экземпляр SFU. В одном процессе их может быть несколько. `close()` идемпотентен |
| `SfuConfig` | UDP-порт и адрес, шарды, `joinPolicy`, размер буфера событий |
| `JoinPolicy` / `JoinRequest` / `JoinDecision` | Допуск хостом: `credentials` — его токен. `Allow(participantId)` — его id пользователя, новая сессия с тем же id вытесняет старую |
| `join(request, sink)` / `onMessage` / `leave` | Сигнализация по транспорту хоста. `SignalSink` — его канал к клиенту |
| `events: SharedFlow<SfuEvent>` | Комнаты, участники, медиа-соединение, «говорит», публикация видео. Не блокирует SFU: при переполнении теряются самые старые события |
| `kick`, `setMuted` | Управление: выгнать (клиенту уходит `bye`), заглушить на стороне сервера |
| `rooms()`, `room()`, `participant()`, `metrics()` | Снимки состояния и счётчиков для мониторинга хоста |

**Совместимость:**
- Встроенная в Kotlin проверка ABI: дампы в `*/api`, `checkKotlinAbi`, обновление через `updateKotlinAbi`. Изменение публичного API видно в ревью.
- Протокол сигнализации версионируется полем `Welcome.protocol`. Неизвестные сообщения и поля игнорируются обеими сторонами.

**Публикация:**
- `maven-publish` для `krtc-protocol`, `krtc-signaling`, `krtc-sfu`, `krtc-sfu-ktor`, `krtc-core`, `krtc-client`.
- Координаты `krtc.group:<модуль>:krtc.version` из `gradle.properties`. Group `krtc` — заглушка до выбора настоящего.

**OpenSSL на нативе** едет внутри klib `krtc-sfu`:
- на macOS — статически;
- на Linux — указание линковать `-lssl -lcrypto`.

Хосту на Kotlin/Native не нужно прописывать флаги линковки.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| SFU отдельным процессом рядом с хостом | Нужен, когда хост на другом языке. Хост на KMP получает прямые вызовы, общий процесс и события без IPC |
| Свой HTTP-сервер внутри ядра | Хост теряет контроль над портами, TLS, авторизацией и маршрутизацией |
| Колбэки вместо `Flow` для событий | `SharedFlow` естественен для корутинного хоста и не даёт медленному обработчику тормозить SFU |

## Последствия

- Хост связывает SFU со своей авторизацией одной функцией `JoinPolicy` и получает события в своём коде.
- Внутренности (комнаты, шарды, SRTP, DTLS) можно менять без ломки хостов, ABI-проверка за этим следит.
- Отдельное приложение `krtc-sfu-server` — тоже пример встраивания: у него нет доступа к внутренностям.

## Как проверено

- `EmbeddingTest` (JVM и macOS-натив):
  - отказ политики;
  - id хоста и вытеснение старой сессии;
  - последовательность событий;
  - `kick` и `setMuted`;
  - два экземпляра в одном процессе;
  - `close`.
- `RoomClientSfuTest`: `krtc-client` против SFU, встроенного в собственный Ktor-сервер теста через `krtc-sfu-ktor`.
- Отдельный внешний проект (вне репозитория) подключает `krtc:krtc-sfu-ktor:0.1.0-SNAPSHOT` из `mavenLocal`, задаёт свою `JoinPolicy` и события. Он собирается для JVM и линкуется в нативный бинарь macOS без флагов OpenSSL, бинарь запускается.
- Приложение `krtc-sfu-server` в Chromium: аудио, видео и simulcast работают как раньше.
