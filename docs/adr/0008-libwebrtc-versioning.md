# ADR-0008. Версии и сборка libwebrtc

- Статус: Предложено
- Дата: 2026-11-09

## Контекст

- libwebrtc выпускается ветками по Chromium milestone примерно раз в 4 недели. На 2026-11-09 stable — **M157** (ветка `8103`).
- Каждая ветка меняет C++ API и получает исправления безопасности.
- Сборка тяжёлая (depot_tools, gn, ninja), а для шима ([ADR-0002](0002-binding-c-abi-shim.md)) нужны собственные бинарники для каждого таргета.

## Решение

1. **Привязка к stable milestone.** krtc собирается из ветки `branch-heads/<номер>` текущего stable Chromium. Обновление — на каждый второй milestone (~8 недель), с внеочередным обновлением при исправлениях безопасности.
2. **Свои патчи** хранятся в репозитории как набор `.patch` файлов (`krtc-native/patches/<milestone>/`) и накладываются скриптом. Каждый патч сопровождается комментарием: зачем он нужен и где взят (webrtc-java, LiveKit, GetStream, свой).
3. **Конфигурации gn** в репозитории для каждого таргета:
   - android arm64/x64;
   - ios arm64 + simulator arm64;
   - macos arm64;
   - linux x64/arm64;
   - windows x64/arm64.

   Общие флаги: `is_debug=false`, `rtc_include_tests=false`, `is_component_build=false`, `rtc_use_h264` по решению этапа 8. Встроенная `libc++` libwebrtc остаётся внутри библиотеки.
4. **Prebuilt-артефакты.**
   - Отдельный CI-пайплайн собирает libwebrtc + шим и публикует архивы с ключом `<milestone>-<хэш патчей и конфигов>`.
   - Пользователи и обычный CI krtc скачивают их, а не собирают.
   - Локальная сборка из исходников остаётся документированной возможностью.
5. **Версия krtc** — semver библиотеки. Milestone указывается в метаданных артефакта и в `Krtc.libwebrtcVersion`, в номер версии не входит.
6. **Обновление milestone** — отдельный PR:
   - новые патчи;
   - адаптация шима;
   - прогон conformance и interop;
   - запись в CHANGELOG с изменениями поведения.

## Альтернативы

- **Зависеть от чужих prebuilt** (stasel/WebRTC, GetStream, webrtc-sdk): не содержат наш шим, и цикл обновлений зависит от чужих людей. Отвергнуто, но их флаги и патчи используем.
- **Следовать каждому milestone**: слишком дорого для небольшой команды. Отвергнуто.
- **Версия krtc = номер milestone** (как у webrtc-kmp `0.125.x`): смешивает изменения API krtc и движка. Отвергнуто.

## Последствия

- Нужен мощный CI-раннер или кэш (sccache или удалённый кэш ninja) для сборки libwebrtc. Это главная инфраструктурная статья расходов.
- Отставание от stable не больше двух milestone, исправления безопасности — по факту выхода.

## Как проверить / когда пересмотреть

- Spike (этап 10): полная сборка M157 для `macosArm64`, замер времени и размера.
- Через два цикла обновления оценить трудоёмкость и при необходимости сменить ритм.
