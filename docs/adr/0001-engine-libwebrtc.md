# ADR-0001. Движок — libwebrtc

- Статус: Предложено (подтверждается spike, этап 10)
- Дата: 2026-11-09

## Контекст

Цель krtc — полное покрытие спецификаций WebRTC и Media Capture ([инвентарь](../../spec/COVERAGE.md): 1143 core-пункта). Кроме API нужны:
- медиадвижок: захват, кодеки (Opus, VP8/VP9, H.264, AV1), AEC/NS/AGC, джиттер-буфер, синхронизация аудио и видео;
- транспорт: ICE, DTLS-SRTP, SCTP, BUNDLE, RTX/NACK/FEC;
- контроль перегрузки: GCC, TWCC;
- simulcast и SVC;
- полная статистика по webrtc-stats.

Это должно работать одинаково на Android, iOS, macOS, Linux, Windows и JVM.

## Решение

Использовать **libwebrtc** (Google, BSD-3) как движок на всех платформах, кроме браузера ([ADR-0003](0003-browser-targets.md)). Версия привязана к ветке Chromium milestone ([ADR-0008](0008-libwebrtc-versioning.md)).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Свой стек на чистом Kotlin (как Pion или webrtc-rs) | Протоколы реализуемы, но медиадвижок (AEC, джиттер-буфер, GCC, аппаратные кодеки) — это годы работы и постоянная гонка за Chromium по interop |
| libdatachannel + своя медиачасть | Отличный транспорт с C API, но без медиадвижка. Свой медиадвижок — та же проблема, что выше |
| Pion или webrtc-rs через FFI | Медиадвижка тоже нет, плюс Go-рантайм в процессе (Pion) |
| Официальные SDK платформ без libwebrtc на desktop | Нет единого покрытия, desktop не закрыт. См. [ADR-0002](0002-binding-c-abi-shim.md) |

## Последствия

- Поведение на проводе совпадает с Chrome, поэтому interop с браузерами беспроблемный.
- Тяжёлая сборка: depot_tools, gn, ninja, десятки гигабайт, часы на таргет. Нужны prebuilt-артефакты и кэш ([ADR-0008](0008-libwebrtc-versioning.md)).
- Размер бинарей: несколько мегабайт на архитектуру даже после strip. Нужно отключать ненужные модули.
- Каждые 4 недели выходит новый milestone с изменениями C++ API, поэтому нужен регулярный процесс обновления.
- Для серверного SFU libwebrtc не подходит. Это решается отдельно ([ADR-0009](0009-server-side-use.md)).

## Как проверить / когда пересмотреть

- Spike (этап 10): libwebrtc M157 собирается для `macosArm64` и `jvm` с нашим шимом, loopback-соединение через DataChannel проходит.
- Пересмотреть, если сопровождение сборки или размер бинарей окажутся неприемлемыми, или если появится зрелый медиадвижок с C API.
