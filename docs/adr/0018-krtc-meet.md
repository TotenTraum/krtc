# ADR-0018. `krtc-meet`: пример приложения для звонков на Compose Multiplatform

- Статус: Принято, этапы M2–M5 впереди
- Дата: 2026-11-11
- Уточняет: [ADR-0012](0012-kmp-client.md), [ADR-0014](0014-spike-krtc-native.md)

## Контекст

Библиотека умеет звонок, simulcast, показ экрана со звуком и сообщения комнаты (ADR-0015 – ADR-0017). Но приложения на ней нет. Неудобные места API (доступ к кадрам, выключение звука и видео, переподключение, выбор устройств) видны только из настоящего приложения. Оно нужно и как образец для тех, кто встраивает krtc.

## Решение

Модуль `krtc-meet`: один код интерфейса на Compose Multiplatform поверх `krtc-client` и `krtc-native`.

| Платформа | Как |
|---|---|
| macOS, Windows, Linux | Compose Desktop на JVM. `krtc-native` через JNI: dylib и `krtc.dll` в jar. Для Linux на JVM нужна своя JNI-библиотека, её пока нет |
| Android | Compose, `krtc-native` через JNI (M2) |
| iOS | Compose (`ComposeUIViewController`), `krtc-native` на Kotlin/Native (M2) |

Устройство:
- **`MeetSession`** (commonMain) — состояние звонка поверх `RoomClient`: вход, участники, речь, экраны, выключение микрофона и камеры. Отдаёт всё через `StateFlow`.
- **`VideoView(track)`** — кадры из `NativeTrack.setFrameListener` (ARGB) идут в переиспользуемые Skia-битмапы с двойной буферизацией. Новый кадр выводится на ближайшем кадре Compose, старые отбрасываются.
- **Платформенное** (`expect/actual`): фабрика и звук, камера, ARGB → `ImageBitmap`.

Этапы:
1. **M1, desktop на macOS:** вход, своё и чужое видео, звук. Режим тестового звука и тестовой картинки, чтобы проверять без микрофона и камеры.
2. **M2:** Android и iOS.
3. **M3:** выбор камеры и микрофона, показ экрана со звуком, чат, состояние «выключен» видно собеседникам (правки в SFU и сигнализации).
4. **M4:** переподключение WebSocket, индикатор качества, раскладки, слой simulcast по размеру плитки.
5. **M5:** сборки dmg, msi, deb, APK и iOS в CI; JNI-библиотека для Linux на JVM.

## M1 (2026-11-11)

- Модуль `krtc-meet` (Compose Multiplatform 1.12.2, JVM): `MeetSession`, `VideoView` с тройной буферизацией, экраны входа и звонка. Звонок: сетка плиток с подсветкой говорящего, экраны собеседников отдельными плитками, кнопки микрофона, камеры и выхода.
- Упаковка: `createDistributable` и `packageDmg`, `.app` с описаниями доступа к камере и микрофону. Переменные окружения `KRTC_MEET_*` позволяют входить автоматически и снимать снимок окна для проверок.
- Проверено: приложение с тестовой картинкой и тестовым звуком в комнате с двумя вкладками Chrome. Chrome получает его видео и звук без потерь. Приложение выводит своё превью и видео Chrome (снимок интерфейса, отрисованный Compose вне экрана), подсвечивает говорящих.
- Не проверено: настоящие камера и микрофон (`PLATFORM`) в `.app` с описаниями доступа — запуск владельцем проекта.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Отдельные нативные приложения (SwiftUI, Jetpack Compose, Swing) | Втрое больше кода, а цель — проверить общий KMP-API |
| Desktop без JVM (K/N + Skiko) | Compose UI под Linux и Windows на K/N нет, для macOS он экспериментальный. Нужен свой хост окна и ввода |
| Вывод видео через `SurfaceView` / `MTKView` / `Canvas` по платформам | Быстрее, но это три разных кода. Сначала общий путь через ARGB; если не хватит, вывод I420 в GPU-текстуру |

## Риски

- **Копирование ARGB.** Четыре плитки 720p30 — это около 400 МБ/с. Ограничиваем слоем simulcast по размеру плитки (M4); дальше — I420 в GPU.
- **Звук `PLATFORM` на desktop мало проверен:** эхоподавление, выбор устройств.
- **Windows и iOS на устройствах** проверяет владелец проекта.
